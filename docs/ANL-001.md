# ANL-001 하의 사진 분석·사용자 확인 최소 계약 (설계안, 미구현)

- 기준: `integration/cur-004-final12-test` d68b7f1 / 브랜치 `design/anl-001-garment-analysis-contract`. 읽은 범위: `docs/GARMENT_API.md`, `backend/src/modules/garment/routes.ts`(GET/PUT/DELETE·image), `backend/src/db/migrations.ts`(garments), `frontend/src/lib/onboarding-api.ts`(Garment 타입).
- 상태: **설계만. 실제 분석은 연결되지 않음.** 현재 `AGENTS.md`·`GARMENT_API.md`는 "이 단계에서 AI 분석 구현 금지" — 구현 착수 전 이 규칙 변경 결정이 먼저 필요. CUR-002 품질점수안은 이 계약에 넣지 않음(제안 유지).

## 1. 원칙
- 분석 추정(`estimates`)과 사용자 확정(`attributes`)을 별도 저장. 분석은 기존 사용자 입력(`garmentType`·`brand`·`productName`·`purchaseUrl`)과 확정값을 **절대 덮어쓰지 않음**. 화면은 추정을 "제안"으로만 보여 주고, 저장은 사용자의 확인 동작으로만.
- 기존 `PUT …/garment`(metadata `.strict()`)와 저장·복원·세션 보호는 그대로. 새 기능은 별도 경로로 추가 → 기존 프론트는 영향 없음.

## 2. 데이터 (추가 마이그레이션, 기존 행 보존)
- `garments.image_sha256 TEXT` 추가: PUT에서 정규화 PNG의 SHA-256 저장(기존 행은 마이그레이션 때 파일을 읽어 채움). 이것이 "사진 버전".
- `garment_analyses(id, garment_id, image_sha256, analyzer, analyzer_version, status, estimates_json, error_code, created_at, completed_at)`, `UNIQUE(garment_id, image_sha256, analyzer, analyzer_version)`.
- `garment_attributes(garment_id PK, color, silhouette, material_feel, confirmed_for_sha256, based_on_analysis_id NULL, updated_at)`. 값은 정해진 어휘(enum) 또는 null.
- 세션/하의 삭제 시 함께 삭제(기존 DELETE 트랜잭션에 포함). 마이그레이션 번호는 INT-001-A의 v4 제안과 함께 조정.

## 3. API (모두 기존 쿠키 세션·`X-Onboarding-Request: 1`·Origin 검사 동일)
| 메서드 | 경로 | 결과 |
|---|---|---|
| POST | `/api/onboarding/session/garment/analysis` | 202 `{analysis}`(queued). 같은 사진·같은 분석기 결과가 있으면 새로 돌리지 않고 200 `{analysis, reused:true}` |
| GET | `…/garment/analysis` | 200 `{analysis: null \| {...}}` — 현재 사진(sha) 기준 최신 1건만 |
| PUT | `…/garment/attributes` (JSON) | 200 `{attributes}`. body `{color, silhouette, materialFeel, basedOnAnalysisId \| null}` |
| GET | `…/garment` (기존) | 추가 필드만: `imageVersion`(sha 앞 16자), `attributes`(없으면 null). 기존 필드 불변 |

- `analysis` 모델: `{id, imageVersion, status: queued|running|completed|failed|unavailable, analyzer, estimates: {garmentType:{value,confidence}, colors:[{name,hex,confidence}], silhouette:{value,confidence}, materialFeel:{value,confidence}}, needsConfirmation:["color",…], requestProductInfo: boolean, createdAt, completedAt, error:{code}|null}`
- `requestProductInfo=true`(특정 불가·신뢰도 낮음)이면 화면이 기존 브랜드·제품명·구매 링크 입력을 권함. 서버는 링크를 방문하지 않음(기존 규칙 유지).
- 오류: 401 SESSION_REQUIRED, 403 REQUEST_HEADER_REQUIRED/ORIGIN_NOT_ALLOWED, 404 GARMENT_NOT_FOUND(하의 없음), 409 ANALYSIS_STALE(`basedOnAnalysisId`가 현재 사진이 아닌 분석), 400 INVALID_INPUT(어휘 밖 값), 429 ANALYSIS_RATE_LIMITED, 503 ANALYSIS_UNAVAILABLE(공급자 미설정 — **현재 상태의 정상 응답**).

## 4. 중복 방지·무효화
- 같은 사진 재방문·재요청: `(garment, sha, analyzer, version)` 유일키로 기존 결과 재사용. 진행 중이면 그 건을 반환. 실패 건만 재시도 허용(쿨다운).
- 사진 교체(PUT에 image 포함): sha가 바뀌므로 이전 분석은 자동으로 "현재 아님". 기존 확정값은 지우지 않고 `confirmed_for_sha256 ≠ 현재 sha`로 표시해 화면에서 "다시 확인 필요"로 미리 채움. 정보만 수정(PUT image 없음)은 분석·확정값 유지.
- 분석기 버전 변경 시에만 같은 사진 재분석 가능.

## 5. 프론트 영향 (Lovable 배정 대상, 이번 작업에서 구현 안 함)
- 저장 성공 후 "사진 분석" 영역: unavailable이면 "분석 준비 중" 정직한 표시, completed면 추정을 제안으로 보여 주고 확인·수정 후 PUT attributes. `onboarding-api.ts`에 타입·함수 추가, 기존 `putGarment`는 변경 없음.

## 6. 최소 검증 기준 (구현 시)
- 분석 결과가 garmentType·brand·productName·purchaseUrl·확정값을 바꾸지 않음. 같은 사진 POST 2회 → 분석 1건. 사진 교체 후 GET analysis는 새 sha 기준(null 또는 새 건), 확정값은 "재확인 필요". 하의 삭제 → 분석·확정값 삭제. 다른 세션 접근 401/404. 공급자 미설정 시 503이고 화면은 완료로 표시하지 않음. 기존 garment 테스트 전부 통과.

## 7. 결정 필요 (사용자·총괄)
1. "AI 분석 구현 금지" 단계 규칙 해제 여부와 시점.
2. 분석 공급자(비전 모델/API)·API 키 보관 위치·사진 1장당 비용 한도·호출 제한.
3. 사진을 외부 공급자로 보내는 것에 대한 개인정보 방침·동의 문구, 분석 결과 보관 기간.
4. 동기 처리(요청 안에서 완료) vs 비동기 큐 — 현재 서버는 단일 프로세스·큐 없음.
5. 색상·실루엣·소재감 어휘 목록(enum)과 브랜드·제품명·링크를 공급자에 함께 보낼지.
