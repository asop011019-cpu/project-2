# COND-001 / M3.1 추천 조건 입력 — 계약안 (검토 전, 미구현)

- 목적: 기존 취향에 계절·상황·격식·추가 구매 예산을 더해 추천 입력으로 저장·복원. AI·유료 호출·상품 검색 없음.
- 기준: `feature/gar-002-garment-details@9d6a569` (GAR-002·R1·재확인 국소 수정 포함). 문서 브랜치 `docs/cond-001-contract`.
- API 계약: [API.md 추천 조건](API.md#추천-조건-cond-001-계약안--검토-전-미구현). 저장: [DATA.md](DATA.md#cond-001-계약안-미구현).
- Lovable 원본에 없는 재확인 수정(`confirmPending`, 테스트 시간 제한)은 [frontend/SOURCE.md](../frontend/SOURCE.md)에 기록돼 있음. 조건 화면 Lovable 요청 때 같은 수정도 함께 넣어 덮이지 않게 함.

## 기존 구조와 선택한 방식

- 취향·기준 옷은 모두 계정의 진행 1개(`onboarding_sessions`)에 FK로 붙고, 진행 삭제·초기화·탈퇴 삭제가 연쇄 삭제로 처리됨. 조건도 같은 방식으로 붙이면 소유권·삭제 연동을 새로 만들 필요가 없음.
- 기준 옷 속성(`garment_attributes`)과 같은 "버전 + JSON 1행" 구조. 새 의존성 없음.
- 기존 어휘와 겹침: 카탈로그 상위 장르의 `men_formal_group`·`women_formal_group`(포멀)은 **취향**이고, 격식 수치·`formal_event`는 **이번 착용 조건**. 자동으로 서로 바꾸거나 채우지 않음. 기준 옷 어휘(v0.2)에는 계절·상황 축이 없어 충돌 없음.
- 격식 행사 + 낮은 격식처럼 어긋나는 조합은 저장은 허용하고, 안내는 M3.2에서 다룸(서버 임의 보정 금지).

## 화면 계약 (Lovable, 승인 후)

- 위치: 새 경로 `/conditions`. 기준 옷 저장 뒤 "코디 조건 정하기"로 이동, 계정 화면에서도 진입. 의류 화면처럼 진입 시 GET으로 복원.
- 계절·상황: 칩 묶음(`role="group"`, 각 칩 `aria-pressed`). "상관없음" 칩은 다른 칩과 배타. 아무것도 누르지 않은 상태가 미입력이며 "아직 안 정함"으로 표시.
- 격식: 처음엔 값 없는 상태("아직 안 정함") + "상관없음" 칩. 조절바를 건드리면 값이 생김. `role="slider"`, `aria-valuetext`(예: "60, 조금 격식"), 키보드 ±10, 손가락 조작용 44px 이상 손잡이와 −/+ 버튼. "선택 지우기"로 미입력 복귀.
- 예산: 금액 칩(5만·10만·20만·30만·50만) + 직접 입력(숫자 키패드, 표시만 쉼표) + "상한 없음". 문구 "갖고 있는 기준 옷 가격은 빼고, 더 살 옷의 참고가 합계예요. 실제 판매가·재고와 다를 수 있어요."
- 저장: 하단 고정 "조건 저장", 바뀐 값이 있을 때만 활성. 저장 중 입력 잠금.
- 로딩: 스켈레톤. 실패: 입력 유지 + 다시 시도. 400: 항목별 문구. 401 `SESSION_REQUIRED`: 입력 유지, 새 시작은 사용자가 선택. 401 `AUTH_REQUIRED`·403 동의: 이동 전에 미저장 입력을 `sessionStorage`에 보관했다가 돌아오면 복원(저장 성공·로그아웃 시 삭제). 토큰·ID는 넣지 않음.

## 테스트 계획

백엔드
1. 처음 GET: 네 항목 null, `updatedAt` null.
2. 저장·재조회·서버 재시작 후 같은 값. 배열은 정해진 순서로 정렬.
3. null과 `"any"`가 각각 그대로 복원(서로 바뀌지 않음). 모두 null PUT → 행 삭제.
4. 400: 어휘 밖·중복·빈 배열·`"any"` 섞기·키 누락·알 수 없는 키·격식 -1/101/50.5/"50"·예산 소수/음수/범위 밖/문자열/`Number.MAX_SAFE_INTEGER` 초과. 실패해도 기존 저장값 유지.
5. 같은 값 재저장 시 `updatedAt` 유지.
6. 다른 계정 조회·수정 불가, 로그인 없음 401, 헤더 없음 403, 진행 없음 401 `SESSION_REQUIRED`.
7. `DELETE /session`·`reset`·탈퇴 삭제 실행 시 행 삭제, 유예 중 복구 시 유지.
8. 범주 전환·옷 사진 교체·종류 변경·옷 삭제 후 조건 유지.
9. v8→v9 마이그레이션이 기존 행 보존.

프론트
1. 상관없음 칩 배타, 미입력 ↔ 상관없음 ↔ 선택 전환 결과가 PUT 본문과 일치.
2. 격식 초기 미입력, 키보드 조작·`aria-valuetext`, 선택 지우기.
3. 예산 쉼표 표시와 정수 전송, 범위 밖 안내.
4. 저장 실패·401 시 입력 유지, `AUTH_REQUIRED` 이동 후 복원.
5. 375px에서 하단 바가 입력을 가리지 않음(실제 브라우저 확인).
