- 기준: `feature/gar-002-garment-details@9d6a569` (GAR-002·R1·재확인 국소 수정 포함). 작업 브랜치 `feature/cond-001-conditions`.
- API 계약: [API.md 추천 조건](API.md#추천-조건-cond-001). 저장: [DATA.md](DATA.md#cond-001).

## 결정 (2026-10-28, 사용자 지시로 총괄 회신 없이 진행)

| # | 항목 | 적용 | 근거 |
| --- | --- | --- | --- |
| 1 | 계절 → **기온 범위** | 사용자 제안. 최저~최고 두 손잡이 바, -20~40°C 정수 | 같은 계절이라도 기온 차가 커서 옷이 달라짐. 일교차를 그대로 넣어 겹쳐 입기 판단 가능 |

| 3 | 예산 | 10,000~5,000,000원 정수 + 상한 없음 | 0원은 옷장 없이 추천 불가. 상한은 0 하나 더 붙인 오입력 방지 |
| 4 | 진행 초기화 | 조건도 삭제 | 기존 "모든 기록 삭제" 정책과 같음 |
| 5 | 미입력 | 추천을 막지 않고 "조건 없음" | 첫 사용 흐름을 길게 만들지 않음. 안내는 M3.2 |

## 기존 구조와 선택한 방식

- 취향·기준 옷은 모두 계정의 진행 1개(`onboarding_sessions`)에 FK로 붙고, 진행 삭제·초기화·탈퇴 삭제가 연쇄 삭제로 처리됨. 조건도 같은 방식이라 소유권·삭제 연동을 새로 만들지 않음.
- 기준 옷 속성(`garment_attributes`)과 같은 "버전 + JSON 1행" 구조. 새 의존성 없음.
- 기존 어휘와 겹침: 카탈로그 상위 장르의 포멀 그룹은 **취향**, 격식 수치·`formal_event`는 **이번 착용 조건**. 서로 자동 변환하지 않음. 기준 옷 어휘(v0.2)에는 기온·상황 축이 없어 충돌 없음.
- 격식 행사 + 낮은 격식처럼 어긋나는 조합은 저장 허용, 안내는 M3.2(서버 임의 보정 금지).
- 날씨 자동 불러오기는 위치 정보가 필요해 이번 범위에서 제외.

## 화면 계약

- 위치: 새 경로 `/conditions`. 기준 옷 화면에서 "코디 조건 정하기"로 진입. 진입 시 GET으로 복원.
- 기온: 두 손잡이 바(-20~40°C, 1도 단위). 처음엔 "아직 안 정함", "상관없음" 칩. 바 아래 구간 말(추움·쌀쌀함·선선함·따뜻함·더움)과 선택 값 "8°C ~ 20°C". 손잡이별 `role="slider"`, `aria-valuetext`, 키보드 ±1, 44px 이상 손잡이, 각 끝 −/+ 버튼, "선택 지우기".
- 상황: 칩(`aria-pressed`), 1개 선택. "상관없음" 칩은 배타.
- 격식: 처음 미입력 + "상관없음". 바(0 편안함~100 격식, 10 단위) + −/+ 버튼, `aria-valuetext`, "선택 지우기".
- 예산: 금액 칩(5만·10만·20만·30만·50만) + 직접 입력(숫자 키패드, 표시만 쉼표) + "상한 없음". 문구 "갖고 있는 기준 옷 가격은 빼고, 더 살 옷의 참고가 합계예요. 실제 판매가·재고와 다를 수 있어요."
- 저장: 하단 고정 "조건 저장", 바뀐 값이 있을 때만 활성. 저장 중 입력 잠금.
- 로딩: 스켈레톤. 실패: 입력 유지 + 다시 시도. 400: 항목별 문구. 401 `SESSION_REQUIRED`: 입력 유지, 새 시작은 사용자가 선택. 401 `AUTH_REQUIRED`·403 동의: 이동 전에 미저장 입력을 `sessionStorage`에 보관했다가 돌아오면 복원(저장 성공 시 삭제). 토큰·ID는 넣지 않음.
