## Goal

한국의 일반 사용자가 마음에 들어 구매한 하의(바지·치마) 사진 한 장을 등록하면, 취향·계절·상황·격식·추가 구매 예산에 맞는 서로 다른 실제 상품 코디를 발견하고 AI 표준 모델의 전체 착장 예시로 확인하는 모바일 웹앱을 만든다. 이후 실제 사용자 시험과 운영 준비를 거쳐 배포한다.

현재 마일스톤: 제한된 검증 상품과 시험 사진으로라도 **사진 등록 → 분석·사용자 확인 → 조건 입력 → 상품 검색 → 복수 코디 생성 → AI 착장 표시**를 실제로 연결한 비공개 시험 버전. 수동 입력만 또는 모의 AI 결과만으로 이 마일스톤을 완료 처리하지 않는다.

성공 판단: 전체 흐름의 실행 증거, 상품 실재·예산 계산 정확성, 사용자가 평가한 코디 완성도·현실성, 착장 이미지의 상품 디테일 일치. 구매 전환은 별도 사업 지표다. 사용자 시험의 수치 목표·표본·기간은 시험 전에 정하며 임의로 확정하지 않는다.

## 운영·판정 원칙

- 코딩 담당 Claude Code는 백엔드·통합을 담당하고 Lovable에 직접 지시·결과 확인한다. 크레딧 잔량 동안 Lovable은 프론트·디자인, 소진 후 Claude Code로 통합. GPT는 목표·우선순위·중요 결정·완료 검토 담당.
- 모든 지시는 상위 Main 항목과 해당 Sub 항목, 기준 저장소/브랜치/SHA, 수정 범위·보존 기능, 입력/출력 계약, 완료 기준·검증 방법, 회신 대상을 포함한다.
- 진행 평가는 자료/설계, 구현, 코드 검토, 실행 검증, 통합, GitHub 반영, 배포를 구분한다. 결과물과 증거를 확인한 세부 항목만 완료 표시한다.
- 연관 없는 준비 작업은 가능하면 진행하되, 구현이 의존하는 계약·데이터는 먼저 확인한다. 한 담당자의 같은 파일·브랜치를 동시에 수정하지 않는다.
- 기존 코드·사용자 변경 보존. 인증 보완을 무기한 반복하여 핵심 흐름의 준비를 막지 않는다. main 병합과 공개 배포는 별도 판단.
- 사진 분석·이미지 생성 공급자와 비용 상한은 미정. 후보 비교·모의 검사 준비는 가능하나 새 유료 호출·공개 서비스·사진 전송 조건은 확정 후 진행한다.
- 사용자 사진 자체 학습 금지. 무신사·유니클로 자료는 비공개 시험 한정. 실제 상품 기반 코디와 실제 상품을 정확히 재현한 이미지는 별도 검증 대상이다.
