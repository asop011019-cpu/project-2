# Gemini에 붙여 넣을 프롬프트

아래 본문을 Google AI Studio의 Gemini에 전달하세요. 먼저 이 GitHub 저장소의 최신 변경을 가져와야 합니다.

---

너는 `https://github.com/asop011019-cpu/project-2`의 프런트엔드 개발자이자 제품 디자이너다. Codex가 `backend/`에 최초 취향 수집용 API·DB·인증·검증을 구현했다. 너는 **온보딩 UI와 API 연결만** 담당한다.

먼저 저장소·현재 브랜치·미반영 변경·기존 화면을 확인하고 `AGENTS.md`, `docs/API.md`, `docs/GEMINI_HANDOFF.md`, `docs/DATA.md`, `docs/CONTENT.md`를 읽어라. 기존 UI/디자인이 있으면 보존하고 필요한 모듈만 수정한다. UI가 없다면 `frontend/`에 모바일 우선 UI를 만들되 백엔드를 다시 구현하거나 root/backend 설정을 덮어쓰지 않는다. 백엔드 계약을 임의로 바꾸거나 저장소를 localStorage로 대체하지 않는다.

사용자 흐름은 다음과 같다.

1. 첫 화면은 추천받을 의류 범주 남성복/여성복 두 카드만 제공한다. 성별 정체성을 묻지 않는다. 선택을 서버에 저장한 뒤 자연스럽게 다음 화면으로 이동한다.
2. API가 제공하는 상위 장르를 안내하고, 선택한 범주의 하위 스타일을 한 번에 하나씩 탐색한다. 이름·설명·순서·이미지·진행률은 서버 응답을 사용하며 12개나 스타일 목록을 UI에 하드코딩하지 않는다.
3. 스타일 상세의 실제 이미지 4–6장을 사진 중심으로 보여준다. model_outfit / flat_lay / collage를 모두 지원하고 isGenerated 표시를 반영한다. 모바일 2열·데스크톱 3열을 기본으로 하고 전체 옷과 신발이 잘리지 않게 contain으로 표시한다. 하트와 확대 클릭 영역을 분리하고 원본 확대 후 초점·스크롤·선택을 복원한다.
4. “이 스타일 좋아요”=liked, “취향이 아니에요”=disliked, “건너뛰기”=skipped를 명시적으로 선택해야 이동한다. 자동 타이머는 없다. 미응답 null과 건너뛰기는 다르다. 여러 스타일에 좋아요할 수 있고 사진 선호는 스타일 응답과 독립적이다.
5. 이전 이동·범주 변경·새로고침 시 서버의 위치와 선택을 복원한다. 결과 화면에는 선택 범주, 좋아한 스타일과 사진, 응답 수정 기능을 둔다. 좋아한 스타일이 없어도 “아직 취향을 탐색 중이에요”로 자연스럽게 진행한다. 취향이 정확히 확정됐다고 말하지 않는다.
6. 완료는 progress.canComplete와 서버 응답을 따른다. 완료 후 취향을 수정하면 서버가 다시 진행 중으로 열 수 있으므로 재완료 UI를 반영한다. 삭제·초기화는 모든 범주 기록이 지워짐을 설명한 뒤 사용자가 선택한 경우에만 호출한다.

API 연결 시 반드시 지킬 사항:

- 앱 시작은 POST `/api/onboarding/session` `{}`를 한 번만 호출한다. 쿠키가 없으면 생성(201), 유효한 쿠키가 있으면 기존 상태(200)다. 이후 GET으로 복원/재조회할 수 있다. 동시에 여러 초기화 요청을 보내지 않는다.
- fetch는 상대 경로와 credentials: include를 사용한다. POST/PUT/DELETE에는 Content-Type: application/json 및 X-Onboarding-Request: 1 헤더를 보낸다. HttpOnly 쿠키나 토큰을 JavaScript/localStorage에서 읽고 저장하지 않는다.
- 프런트엔드 개발 서버는 `/api`와 `/media`를 백엔드 포트 3001로 프록시한다. 백엔드 PUBLIC_ORIGIN을 실제 프런트엔드 출처와 맞춘다. 운영은 동일 출처 HTTPS를 사용한다. 인증 검사를 제거하거나 CORS를 임의 개방하지 않는다.
- 스타일 응답 저장 시 `{response,nextStyleId:session.navigation.nextStyleId}`를 보내면 응답·이동이 함께 저장된다. nextStyleId 생략은 위치 유지, null은 결과 화면이다. 이전 이동은 position API를 사용한다.
- 하트는 이미지 ID 경로에 `{selected:true}` 또는 `{selected:false}`를 보낸다. toggle 요청이나 이미지 URL 저장을 만들지 않는다. 하트 저장으로 다음 스타일로 이동하지 않는다.
- 변경 요청을 직렬화하고 저장 성공 전 다음 화면/저장 성공을 확정하지 않는다. 400/401/403/404/409/422/500, 로딩, 네트워크 실패, 이미지 로딩 실패를 구분해 처리한다. 오래된 응답이 새 화면을 덮어쓰지 않게 한다.
- `activeStyleOrder`, `styles`, `currentStyleId`, `progress`, `responses`, `imagePreferences`가 진실의 원본이다. 같은 이름의 다른 범주 응답을 합치지 않는다. catalogChanged라고 자동 새 목록으로 교체하지 않고 명시적 refresh-catalog 선택만 제공한다.
- 401 복원 실패 때 기록을 조용히 초기화하지 않는다. 새 시작을 명시적으로 선택한 경우에만 DELETE session → POST session 순서로 처리한다.

현재 **24개 스타일 정의는 있지만 실제 이미지 0장, 탐색 가능한 스타일 0개**다. 정상 응답의 contentStatus=not_ready는 오류가 아니다. 콘텐츠 준비 중 화면을 정식 상태로 구현하고 가짜 URL·무관한 사진·중복 이미지·무단 수집·런타임 mock 대체로 채우지 않는다. 사진 포함 UI는 격리된 테스트 fixture로 검증할 수 있으나, 실제 콘텐츠까지 완성했다고 보고하지 않는다. 이미지 제작·등록은 별도 작업이다.

의류 분석·상품 검색·코디 추천·구매 링크·옷장 기능은 아직 없다. 구현된 것처럼 버튼이나 결과를 만들지 말고 온보딩 완료·취향 수정까지만 연결한다.

짧은 수정 계획을 먼저 제시한 뒤 실제 UI를 구현하고 확인하라. 완료 시 변경 파일, API 연결, 실행·프록시 설정, 확인한 동작, 실제 이미지 부족, 미구현 기능, 커밋/브랜치를 보고하라.
