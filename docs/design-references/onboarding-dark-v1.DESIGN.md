# 온보딩 디자인 기준

이번 사용자 지시에 따라 의류 범주 선택, 상위 장르 탐색, 하위 스타일 사진 묶음, 사진 확대, 결과 확인·수정, 완료 화면 전체에 적용한다. 기능 요구사항과 서버 계약을 디자인 문서보다 우선한다.

## 참고 원문과 적용 범위

- [getdesign의 Spotify 참고 문서 전문](docs/design-references/spotify.DESIGN.md)을 별도 파일로 보존했다. 이는 제3자가 작성한 영감용 문서이며 Spotify의 공식 디자인 시스템이나 자산 사용 허가가 아니다.
- 설치 전 루트 및 프로젝트 안에 기존 `DESIGN.md`는 없었다. `getdesign@0.6.26`의 README·CLI 도움말·실제 옵션을 확인하고 `npx getdesign@latest add spotify --out docs/design-references/spotify.DESIGN.md`로 확보했다. `--force`는 쓰지 않았다.
- 원문과 npm 배포 템플릿의 바이트가 일치한다. [출처·SHA-256 기록](docs/design-references/spotify.source.json)을 함께 둔다. 배포처 웹 페이지는 HTTP 403이었고, 안내된 공식 npm 배포본으로 문서를 확보했다.
- `frontend-design`을 구현 기준으로, `web-design-guidelines`를 구현 후 검토 기준으로 쓴다. 스킬의 일반적인 취향보다 이번 문서와 사용자의 명시적 요구를 우선한다.
- Spotify 로고, 음악 플레이어, 재생 버튼, 앨범·아티스트·곡 정보, 불필요한 검색·회원가입·추천 메뉴는 추가하지 않는다.

한글 버튼에는 영문 대문자 변환과 넓은 자간을 적용하지 않는다. 장르 이름과 사진을 중심으로 두고, 긴 설명·장식·통계를 앞세우지 않는다. 장르 목록은 모바일 가로 탐색, PC 왼쪽 탐색으로 표시한다. 음악 플레이어 대신 현재 작업에 필요한 이전·다음·명시적 건너뛰기만 둔다.

## 사진과 선택 상태

- 현재 프로젝트에는 실제 사진이 없다. `not_ready`를 정상 상태로 표시하고, 준비 중인 이미지 영역에는 하트·확대·스타일 응답을 만들지 않는다. 자리표시자는 실제 사진이나 선택 결과가 아니다.
- 실제 게시 사진은 서버의 `thumbnailUrl`, 확대는 `originalUrl`을 사용한다. `model_outfit`, `flat_lay`, `collage`를 모두 표시한다. `width`, `height`, `alt`와 생성 이미지·제작자 정보를 활용한다.
- 모바일 2열, 중간 폭 3열, 넓은 PC 4열의 기본 배열. 3:4 받침면 안에서 `object-fit: contain`으로 원본 비율·신발·전체 착장을 보존한다. 실제 원본을 밝게 하거나 색을 보정하는 CSS 필터·블렌딩·이미지 생성 대체를 쓰지 않는다.
- 어두운 옷이 앱 배경에 직접 붙지 않도록 밝은 받침면과 여백을 둔다. 원본 자체가 불투명한 어두운 배경이면 그 배경도 보존한다. 소재의 실제 식별성은 원본 사진 등록 후 검토해야 한다.
- 사진 하트는 이미지 바깥의 별도 버튼이며 `aria-pressed`로 상태를 알린다. 초록 외곽선·채워진 하트·레이블을 함께 써서 색만으로 선택을 전달하지 않는다.
- 스타일 좋아요·취향 아님·건너뛰기는 별도 응답이다. 사진 하트는 다음 이동이나 스타일 응답을 만들지 않는다.
- 이미지를 가리는 큰 텍스트나 선택 오버레이를 두지 않는다. 원본 확대는 native dialog로 포커스를 가두며 Escape·닫기·배경 클릭으로 닫고 기존 스크롤과 포커스를 복원한다.
- 하단 조작 영역은 사진 스크롤 영역 밖에 공간을 예약해 사진·설명을 덮지 않는다. 오류·미준비·불러오는 상태도 같은 디자인 체계를 쓴다.

## 기능 계약 보존

- 의류 범주는 성별 정체성이 아니다. 목록·설명·준비 상태는 API에서 가져온다.
- 상위 장르는 한 번에 하나씩 보여주는 탐색 안내다. 클릭은 위치 이동이며 장르 전체에 대한 좋아요나 복수 장르 선호를 저장하지 않는다.
- 하위 스타일은 `activeStyleOrder`에 포함된 실제 탐색 대상만 저장할 수 있다. 여러 묶음으로 보여주되 세션의 고정 목록·카탈로그 버전·완료 기준을 바꾸지 않는다. 초안 이름은 `styleDefinitions`에서 안내한다.
- 이전·다음 장르는 해당 장르에 활성 스타일이 있을 때 `PUT /session/position`으로 위치를 저장한다. 미준비 장르는 저장할 스타일 ID가 없으므로 장르 안내 위치만 URL에 유지한다. URL은 선호 저장소가 아니다.
- 스타일 응답은 저장 후 같은 묶음 안에 유지한다. 명시적인 ‘미응답 스타일 건너뛰기’만 해당 묶음의 미응답 스타일에 skipped를 저장한다. 이미 응답한 취향은 보존한다. 일부 저장 실패 시 성공한 응답은 반영하고 실패 지점에서 멈추므로 재시도가 중복 저장을 만들지 않는다.
- API 쿠키 인증과 서버 저장을 사용한다. localStorage·sessionStorage·자동 mock 대체는 없다. 서버 완료 조건을 따른다. 이미지가 하나도 없으면 완료할 수 없다.
- 완료 후 실제 선호를 바꾸면 서버가 반환하는 진행 중 상태를 반영한다. 추천·의류 분석·구매·옷장 기능은 추가하지 않는다.

## 접근성·검토

native 버튼과 dialog, 키보드 접근, 44px 주요 터치 영역, 즉시 보이는 3px 포커스, 읽을 수 있는 대비, `prefers-reduced-motion`, safe area, 이미지 오류와 재시도를 확인한다. 본문·사진은 원본 의미를 우선한다. 테스트용 fixture는 별도 임시 DB와 개발 포트에서만 사용하며 실제 앱의 콘텐츠나 자동 fallback으로 사용하지 않는다.
