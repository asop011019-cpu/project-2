# 배포 직전 할 일

앱 개발을 끝내고 배포하기 전에 아래 항목을 모두 끝낸다. **필수** 항목이 하나라도 남아 있으면 배포하지 않는다.

## ⚠️ 반드시: 카카오 키 재발급 (사용자 직접)
- [ ] **반드시** 카카오 REST API 키 재발급. 개발 중 쓴 키 2개(처음 키, 2026-10-26 교체한 지금 키)는 모두 채팅에 붙여 넣은 이력이 있어 노출된 것으로 본다.
- [ ] **반드시** 카카오 클라이언트 시크릿 재발급. 개발 중 시크릿 화면이 스크린샷으로 채팅에 노출된 이력이 있다.
- [ ] 새 키·시크릿·Admin 키는 운영 서버 환경변수(`KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`, `KAKAO_ADMIN_KEY`)에만 넣는다. 채팅·Git·로그·스크린샷에 넣지 않는다.
- [ ] 재발급 뒤 이전 키로 로그인이 안 되는지, 새 키로 로그인·탈퇴(연결 끊기)가 되는지 운영 주소에서 확인한다.

## 카카오·접속 설정
- [ ] 카카오 콘솔에 운영 도메인 Redirect URI 등록, `KAKAO_REDIRECT_URI`와 정확히 일치 (`docs/AUTH-002.md`).
- [ ] `PUBLIC_ORIGIN`은 운영 HTTPS 주소 (HTTPS면 `__Host-` 쿠키·Secure 자동 적용).

## 동의 문서·콘텐츠
- [ ] 동의 문서의 "[개발용 초안 · 법률 검토 전 · 운영 사용 금지]" 제거: 법률 검토 후 새 버전으로 게시하고 운영자·개인정보 보호책임자·연락처를 채운다 (`backend/src/modules/auth/consent-documents.ts`).
- [ ] AI 분석 공급자를 정하기 전에는 사진 전송 동의 문서의 [미정] 항목을 공개하지 않는다.
- [ ] 권리 확인 전 사진(내부 테스트용)이 배포 결과물에 들어가지 않았는지 확인.

## 운영 점검
- [ ] 업로드 메모리·요청량 제한 검토, DB·사진 백업과 복구 절차 (`docs/GARMENT_API.md`).
